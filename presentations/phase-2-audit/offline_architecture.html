08 / WP5 TARGET DESIGN

WRITE-AHEAD ARCHITECTURE

The mobile workflow must make field work durable before it relies on a network connection.
Foreman actionCheck-in, evidence, materials, completion
→
IndexedDB queuePersistent mutation and Blob payload
→
Idempotent server writeExactly-once durable application
01 / PERSIST FIRST

Write ahead of network

Enqueue every mutation in IndexedDB before a network attempt so work survives force-quit and reboot.

02 / IDENTIFY ONCE

Use client UUIDs

Each queued mutation carries its own v4 idempotency key; replaying it must never create another record.

03 / RESPECT CAUSALITY

Drain dependencies in order

Check-in applies before materials; required materials and evidence apply before completion is submitted.

04 / HANDLE BINARY SAFELY

Queue Blobs, not Data URLs

Photos and signatures remain binary Blobs in local storage to avoid inflated device quota consumption.

Server requirement: enforce uniqueness on (organizationId, idempotencyKey) so a second drain is a successful no-op.
