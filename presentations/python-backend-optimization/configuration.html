Configuration control 05

Fail fast, then complete the contract

Environment validation now prevents an invalid production start. The next P0 task is to reconcile the complete client/server configuration interface—not to add more silent fallbacks.

Before remediation

Validation could degrade into fallback

safeParse logged invalid configuration but continued with raw process.env values.

  • Missing secrets could become empty strings.
  • Operational handover was harder to diagnose.
Implemented and verified

Invalid production configuration exits

The Zod schema continues to validate required URLs, secret length and declared fields.

  • Validation errors are reported by field path.
  • Invalid production configuration calls process.exit(1).
P0 closure required

One explicit environment contract

Reconcile every variable used by server, client build, OAuth and deployment documentation.

  • Model actual client-required values, including VITE_OAUTH_PORTAL_URL where required.
  • Test the production-start failure path directly.
Why a corporate reviewer will care
Configuration is an API between source code and the operating environment. A strict schema makes the failure mode early and diagnosable; a complete variable inventory prevents the more subtle failure of one tier assuming configuration that another tier neither validates nor documents.
