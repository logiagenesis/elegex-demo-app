# Elegex Protected Procedure Catalogue

> **Contract boundary:** every business procedure below is authenticated, resolves the caller’s active organization membership server-side, and derives `organizationId` from that membership. No client request can choose its own tenant scope.

## Authorization model

| Role    | Read workspace data | Create and update records | Archive records / move controlled job stages | Workspace, staging, and connector administration |
| ------- | ------------------: | ------------------------: | -------------------------------------------: | -----------------------------------------------: |
| Viewer  |                 Yes |                        No |                                           No |                                               No |
| Member  |                 Yes |                       Yes |                                           No |                                               No |
| Manager |                 Yes |                       Yes |                                          Yes |                                               No |
| Admin   |                 Yes |                       Yes |                                          Yes |                                              Yes |
| Owner   |                 Yes |                       Yes |                                          Yes |                                              Yes |

## Error and validation conventions

Invalid request shapes are rejected by Zod at the procedure boundary. Authentication failures return `UNAUTHORIZED`; role failures return `FORBIDDEN`; tenant-bound relationship mismatches are rejected before dependent writes or object-storage uploads. Cross-table task, job, document, and invoice flows run in transaction boundaries so the primary row, notification/activity side effects, and audit records cannot partially succeed.
